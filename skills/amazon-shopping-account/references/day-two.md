# Day 2: one shopping account

1. Reopen and verify the original dedicated profile. Inspect the live Amazon page first. If already signed in to the intended account, verify completion instead of resubmitting registration. If a different account or an existing registration is indicated, stop and report it; do not enter account recovery or create an alternate identity.
2. Before new registration, run `setup_access.py signup-start ACCOUNT_ID --service EXACT_RETURNED_SERVICE_NAME` using the current Amazon shopping service from `providers.py phone-services`. It checks the assigned email, current SMS quote, balance, spending cap, and attempt allowance before entering signup. With a saved `sms_enabled: false`, omit `--service`; only email is checked and a later phone requirement becomes a blocker. It refuses to proceed before completed Day 1 and its next calendar date. Check `phone-check` results to resolve a failed readiness gate; never increase limits automatically. A late invocation can proceed after the eligible date. Do not change the clock or saved date to bypass it. If phase is already `signup`, reconcile the live form and any allocated number rather than restarting registration.
3. Read `email.md` and reuse the inbox assigned during setup; missing access requires reconnection, not another signup. Use the user's provided name. Let the user enter a password directly or use their authorized secret manager. Never save the password in the config, state, or chat.
4. Follow the current visible registration form. Use the exact assigned email. Record only fields and results needed to resume, without secrets. Do not assume button labels or mandatory fields from previous runs.
5. Handle a pending email verification through `email.md`. Only if the form requests a phone number, read `phone.md` and use a one-time TextVerified SMS verification. Do not rent, renew, or upgrade a number.
6. Treat a timeout after submission as uncertain. Inspect the current page and intended account state before any retry. Stop for account restrictions; do not rotate numbers, profiles, addresses, or networks to continue.
7. Confirm a signed-in page showing the intended email/account identity. Inspect the cart without assuming the guest cart transferred. Do not rerun Day 1 or replace missing cart items automatically.
8. Record `workflow.py signup-complete ACCOUNT_ID --evidence BRIEF_OBSERVED_CONFIRMATION`. This command records the agent's observation, not an independent verification. If a schedule exists, it marks that task as needing removal; it does not delete the scheduler task. Follow `scheduling.md` to remove that exact task and record confirmed removal. If cleanup fails, keep the workflow complete, report cleanup pending, and retry only cleanup on a later invocation. A manual run with no schedule needs no scheduler cleanup.
9. Report actual results and the profile shortcut. State that the one-time number is temporary and future access is not guaranteed, and identify any remaining user action.

The skill authoring request alone authorizes no live signup, paid number allocation, or scheduling. A later request to run it is the execution scope. Use existing authorization without repeatedly asking for the same action, while honoring configured spending and attempt limits.
