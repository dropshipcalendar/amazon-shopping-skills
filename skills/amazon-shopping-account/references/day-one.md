# Day 1: signed-out product browsing

Prerequisites: observed dedicated profile and Amazon signed out. Use the account config's product allowlist, populated automatically from [the bundled 50-name list](../assets/product-allowlist.json) at initialization unless explicitly overridden. Do not request names or invent additional categories. This is ordinary product exploration; it does not promise or attempt to alter verification decisions.

1. Run `workflow.py browse-start ACCOUNT_ID`. This establishes Day 1's local date, the next eligible calendar date, and a timer. Never register, create an inbox, or obtain a phone number during this phase.
2. Search Amazon using only configured product names. Select a subset that fits the five-minute budget; there is no requirement to visit all 50 categories. Treat each name as a search category and confirm the result actually matches it. Open a relevant result, inspect its title/variant, and record observed pages with `workflow.py viewed ACCOUNT_ID --product ALLOWLIST_NAME --url OBSERVED_HTTPS_URL`.
3. Before adding an item, check the live guest cart for existing products and record an intent using `workflow.py cart-intent ACCOUNT_ID --product ALLOWLIST_NAME --url OBSERVED_PRODUCT_URL`. The helper rejects duplicates and enforces the cap. Perform the UI action once with quantity 1. Confirm it on the page, then call `workflow.py cart-confirm ACCOUNT_ID --action-id RETURNED_ID`.
4. An unconfirmed intent is uncertain, not failed. Inspect the cart before doing anything else. Confirm it if it succeeded, or use `cart-not-added --action-id ID` only when the live page proves it did not. Never reuse an uncertain intent to click twice. Skip ambiguous products/variants and actions requiring sign-in. Do not compensate by adding an unrelated item.
5. Use `status` between useful browsing actions to check remaining seconds. Continue relevant product viewing until the 300-second active budget expires. Do not add random waits or pretend to browse to imitate a person. Inactivity is not browsing evidence.
6. At the limit, run `browse-stop --result completed`. If interrupted, pause promptly with `browse-stop --result interrupted` and resume later with `browse-start`. The helper stores elapsed time, not proof of UI activity; never mark completion based solely on a timer while idle.

If the previous process crashed and state still says the timer is active, run `browse-recover --observed-seconds N` with only the portion supported by recorded actions. This excludes unknown idle time and avoids duplicate work. If evidence is missing, use zero and inspect existing cart intents first.

Day 2 remains unavailable until this routine is complete and the next calendar date has arrived. After completion, follow `scheduling.md` to confirm the existing same-chat continuation and report its intended time; do not create a duplicate or stay alive overnight. Preserve the guest cart; its persistence through registration is not guaranteed.
